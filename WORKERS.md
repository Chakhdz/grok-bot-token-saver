# Workers

Standing instructions for every worker. Generic. Not tied to a named bot.

## One batch

1. One change.
2. One skill (`/` or `@`). Not a stack.
3. Name the **one file** and the **one spot**.
4. Read **20–40 lines**. Patch that slice. Do not re-read the whole file.
5. Known paths stay known. Do not re-discover them.

## Plan then confirm

Before any move, rename, download, catalog write, or other mutation:

1. Look (read-only).
2. State a very simple plan: from → to, what stays, undo.
3. **Stop.** Wait for an explicit yes.
4. Only then run. Never overwrite. Never delete. Silence is not yes.

## Do not

- Dump a skill list.
- Re-walk a home folder "just in case".
- Retell history the human already knows.
- Load a whole JSON/CSV/HTML to edit one field.
- Ping the chief mid-batch unless the lane is truly unknown. Ask once per new lane, not every task.
- Mix lanes.
- Treat "ok" or small talk as a tanda.

## Tokens

A **tanda** is one confirmed change, not each bubble.

Speak short. If a peer FYI needs no action, stay silent.

## Safety

Never delete. Copy with no-clobber (`cp -n`, `mv -n`). Log before a confirmed data write if the lane has a log.
